# SănDeal (shopass) - deep audit and strengthening plan

Date: 2026-07-06. Scope: full repo (services, db, secrets, obs, region, web, extension, deploy, CI, docs) plus market research. Goal: make the product production-ready and turn it into a client/lead machine. 58 recommendations (R1-R58), each with evidence, action, effort (S = under a day, M = days, L = a week or more), and impact.

Companion docs: `docs/AUDIT-REPORT.md` (code quality, honest), `docs/FR-COVERAGE.md` (74/90 FRs have code; every external touchpoint is a stub). This report does not repeat them; it tells you what to do next and why.

---

## 1. Verdict in one paragraph

The skeleton is real and unusually well documented: the core loop (scrape Shopee -> TimescaleDB -> Prophet/LightGBM forecast -> nightly score -> alert -> chart) runs end to end, the extension has a genuinely strong consent-and-minimization architecture, CI is green across Go/JS/Python, and the docs are honest about stubs. What blocks production is operational, not architectural: the API gateway exists but is not wired in (any caller can forge `X-User-Id`), payments and CAPTCHA and live scraping are stubs, notifications are FCM-only in a Zalo country, there are no backups, no Prometheus, no CD, no LICENSE, and 13,787 of 14,734 tracked git files are `node_modules`. What blocks growth is that the web surface is a placeholder: the root layout still says "Create Next App", there is no pricing page, no analytics, only 4 SEO pages, and the extension cannot be submitted to any store (no icons, no privacy policy). Market timing is on your side: TikTok Shop passed Shopee in VN GMV in Q1 2026 and the incumbent BeeCost does not cover it, while the Honey cookie-stuffing scandal (Rakuten cut Honey off on 2026-01-12) makes trust-first positioning sellable right now.

## 3. Market context (research, 2026-07)

- TikTok Shop reached roughly 41-42% of VN e-commerce GMV in H1 2025 (+148% YoY) and passed Shopee for the first time by Q1 2026; Shopee + TikTok Shop hold ~97% of the top-4-platform GMV (~16 billion USD). Your #1 differentiator is TikTok Shop price history, which BeeCost lacks.
- BeeCost is the incumbent (Shopee, Lazada, Tiki, Sendo): price history, fake-sale detection, coupon finder, with strong past press (GenK, Tiên Phong). It is beatable on TikTok Shop coverage, forecasting ("will it drop?" vs "did it drop?"), cart optimization, and trust transparency.
- Honey (PayPal) was removed from Rakuten Advertising's network on 2026-01-12 and from Impact.com's marketplace after cookie-stuffing and "selective standdown" findings; creator class actions continue. A shopping extension that provably never rewrites attribution except on explicit user click has a story the press will write about. Your PRD already bets on this; the code (user-initiated affiliate only) already complies. You lack only the public proof: open source + transparency page.
- PDPL (Law 91/2025/QH15) has been effective since 2026-01-01 with penalties up to 5% of prior-year revenue. Your comply service scaffolding exists, but consent/DSAR/breach paths are stubs - this is both a legal must and a sales asset ("PDPL-ready by design").

## 4. Part A - ship blockers (do first, mostly small)

R1. Wire the gateway into compose and stop trusting `X-User-Id`. Add the `services/gateway` container to `deploy/docker-compose.yml`, route web/BFF/extension traffic through it, and make authsvc/tracksvc/bff reject direct traffic (network isolation: internal compose network, only gateway published). Effort M, impact critical - this is the single worst security hole.

R2. Purge `node_modules` from git. `git rm -r --cached extension/node_modules web/node_modules`, add to `.gitignore`, commit. 94% of tracked files disappear; clones, diffs, and CI checkouts speed up; secret-scanning noise drops. Effort S, impact high.

R3. Add a LICENSE (dual strategy). Proprietary for services/web; MIT or Apache-2.0 for `extension/` (the PRD's open-source trust moat requires a real OSS license). Add a NOTICE explaining the split. Effort S, impact high (unblocks R44/R49).

R4. Fix root metadata and indexability. Replace "Create Next App" in `web/app/layout.tsx` with real VN title/description templates, default OG image, canonical, `metadataBase`. Effort S, impact high (every shared link and SERP snippet currently embarrasses the product).

R5. Extend the auth guard to the whole `(app)` group. `web/middleware.ts` should protect `/wishlist`, `/alerts`, `/products` too, and redirect with `next=` like `/dashboard` does. Effort S, impact high.

R6. CSRF-protect the auth/refresh BFF routes and add origin checks; add per-IP rate limiting on `/v1/auth/login` at the gateway. Effort M, impact high.

R7. Session restore on reload. Access token lives in a module variable (`web/lib/auth.ts:17`) and dies on refresh even though the httpOnly refresh cookie is valid; call the refresh endpoint on app boot to rehydrate. Effort S, impact high (today every reload looks like a logout).

R8. Extension env-configurable endpoints. `extension/src/sync/ws-client.ts:1` hardcodes `wss://api.sandeal.vn/v1/ext/ws`; move to build-time config (dev/staging/prod) so the extension is testable before prod exists. Also verify you actually own sandeal.vn and decide the final brand/domain (repo "shopass" vs product "SănDeal") before store listings freeze the name. Effort S, impact medium.

R9. Demo/seed separation. `make seed` inserts user 999 / product 100 straight into whatever DB compose points at; guard it behind an `ENV=dev` check so it can never run against prod. Effort S, impact medium.

R10. Align the Go toolchain story: either bump SHIP-GUIDE to 1.25 or pin 1.22 everywhere; add `govulncheck` to CI while you are in there. Effort S, impact low-medium.

## 5. Part B - production operations

R11. TLS + reverse proxy. Put Caddy (you already have the pattern from cyberos `deploy/vps/`) in front of gateway + web with automatic certs for the chosen domain. Effort S-M, impact critical.

R12. Automated backups with restore drills. Nightly `pg_dump` to S3-compatible storage (Backblaze/Wasabi/Vultr object storage) plus WAL archiving (wal-g) for point-in-time recovery; document RTO/RPO; run one restore drill and record it. Effort M, impact critical - price history IS the company asset; losing it resets the moat clock.

R13. Prometheus + alert rules. The OTel metrics and Grafana dashboard exist with nothing scraping them. Add Prometheus to compose, wire the exporters, and define alerts for the NFR targets you already declared: p95 cache <300ms, chart <500ms, 99.5% uptime burn-rate, scrape success rate, alert-send failures, FCM 429s. Effort M, impact high.

R14. Centralized logs. Add Loki + promtail (or Vector -> Loki) to compose so incident investigation does not require ssh + `docker logs` per container. Effort M, impact high.

R15. CI/CD to a real host. Reuse the cyberos pattern you already run in production (GHCR image build on push + SSH roll on a Vultr/other VPS): add build-and-push jobs per service and a deploy workflow gated on CI green. Effort M, impact high - today nothing ships anywhere.

R16. Zero-downtime deploy discipline. Health-check gates on every service in compose (only db has one), graceful shutdown verification (SIGTERM drain), and forward-only migrations with `IF NOT EXISTS` guards; add a migration lint to CI. Effort M, impact high.

R17. Production job scheduling for scrape + forecast. dealsvc already self-crons nightly; scrapesvc and mlforecast are manual one-shots. Options: host cron/systemd timers invoking `docker compose run`, or an in-service ticker like dealsvc. Pick one, document it, and alert when a scheduled run does not happen. Effort S-M, impact critical - without this, "self-running" is not true in prod.

R18. Wire the BFF properly. It is defined in compose but not exposed nor routed behind the gateway; either publish it through the gateway or have web call the gateway directly, and delete the dead path. Effort S-M, impact medium.

R19. Data lifecycle policies. Compression after 30 days exists; add an explicit retention policy decision (e.g., raw `price_snapshot` 18-24 months, `price_daily` aggregate forever) and a documented chunk-size review. Long history is the product, so retention should be a deliberate choice, not a default. Effort S, impact medium.

R20. Load test against NFR targets. One k6 script hitting chart + compare endpoints at expected launch traffic, run in CI weekly, failing on p95 regression - the NFR docs promise this gate; build it. Effort M, impact medium.

R21. Dependency and image hygiene: Dependabot/Renovate, `npm audit` + `govulncheck` + `pip-audit` in CI, Trivy scan on built images, and an SBOM artifact per release. Effort S-M, impact medium.

R22. Run the whole `make smoke` loop in CI nightly against a compose stack (GitHub Actions supports Docker), so the end-to-end loop (seed -> scrape fixture -> deal -> alert row) cannot silently rot. Effort M, impact high.

## 6. Part C - make the stubs real (in revenue order)

R23. Notifications before payments: add Zalo ZNS/OA messaging and email (SES/Postmark) senders next to FCM, honoring the existing `routing.go` channel ranking; Telegram bot as the cheap third channel. In VN, Zalo is where purchase alerts belong; FCM-only means web-push-only reach. Effort M, impact critical for retention (alerts are the product's habit loop).

R24. Battle-test scraping on real targets. Stand up the farm (Playwright) against live Shopee/TikTok/Lazada behind a paid residential proxy (the `HTTPS_PROXY` hook exists), measure block rates, and implement the documented pacing/jitter. Keep robots.txt awareness and per-platform rate budgets in `region/` config - it is both risk hygiene and a sales point. Effort L, impact critical (no live data, no product).

R25. Replace the simulated CAPTCHA solver with a pluggable interface: manual-solve queue first (cheap, legal-clean), commercial solver adapter second, and record solve rates. Effort M, impact high.

R26. ML versioning and evaluation gate. Persist model artifacts with a version + training-window row per run, log MAPE/coverage per model per category, and refuse to publish forecasts whose backtest quality drops below threshold (fall back to Prophet baseline or suppress `p_bottom`). A wrong "buy now" signal is the fastest way to lose the trust moat. Effort M-L, impact high.

R27. Cold-start backfill strategy in code, not just PRD: prioritized seed lists (top categories x top shops), crowdsourced first-visit backfill from the extension, and a "history depth" indicator in the UI so early users see honest partial charts rather than fake-looking full ones. Effort M, impact high.

R28. Payments (MoMo/ZaloPay/VNPay) sandbox integrations with real signature verification, order lifecycle, webhook idempotency, and reconciliation reports - the code paths exist as stubs; certify in each provider's sandbox before launch of paid tiers. Effort L, impact high (but sequence after R23/R24; you can launch free + affiliate first).

R29. Affiliate integration reality check: register for Shopee/TikTok affiliate programs, verify commission windows and deep-link formats per platform in `region/` config, and log attribution events for later reconciliation. This is revenue with zero paywall friction, so it precedes premium. Effort M, impact high.

R30. Social login live test with real Google credentials end to end (JWKS path is only tested against a self-signed token today). Effort S, impact medium.

R31. DNR rules validation tests: assert the packaged `extension/src/dnr/rules.json` actually blocks non-allowlisted hosts in an integration test, since it is a trust-critical claim. Effort S, impact medium.
